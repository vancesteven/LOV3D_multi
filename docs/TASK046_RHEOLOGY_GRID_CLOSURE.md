# TASK-046 raw-grid rheology closure

## Status

CLOSED on 2026-08-20 for the MATLAB/Python lateral-viscoelastic transform and end-to-end Gate C port-fidelity question.

## What was wrong with the earlier comparison

The earlier Python viscoelastic lateral-rheology path synthesized and re-analysed the nonlinear Maxwell field with the SciPy/Gauss-Legendre spherical-harmonic machinery. Native LOV3D MATLAB instead uses its own cell-centred equiangular `SPH_LatLon.m` / `LatLon_SPH.m` transform, including the `Legendre.m` recurrence and the finite-grid FFT phase convention. Comparing outputs generated by those two different transforms produced an apparent floor of order 1e-4 in lateral Love numbers and about 0.75% in lateral energy. That floor was a transform-convention mismatch, not a radial/coupled-solver error.

The MATLAB transform also has a deterministic half-cell longitude phase rotation for m>0 because `SPH_LatLon.m` samples at cell centres while `LatLon_SPH.m` sends the shifted rows directly to FFT without removing the residual half-cell offset. The regression test now pins this native convention rather than incorrectly demanding an identity synthesis/analysis round trip.

## Exact raw-grid coefficient closure

The Python port in `pylov3d/matlab_sph.py` reproduces the native MATLAB nonlinear Io raw-grid rheology spectrum with exactly the same six retained modes:

- (2,-2), (2,0), (2,+2)
- (4,-2), (4,0), (4,+2)

and the same perturbation-order-2 active solution counts `[43, 41, 41]` for the three eccentricity-tide forcings m = 0, -2, +2.

Against the committed native-MATLAB raw-grid coefficient anchor, the worst retained complex-coefficient relative error measured on 2026-08-20 was `1.250e-09`; there were no extra or missing retained modes.

## End-to-end Gate C

The production-quality fractional-grid processor is `pylov3d/rheology_grid.py`. The decisive check is:

```bash
python scripts/io_energy_gate_c_raw_grid.py --nrbase 50 --assert-matlab
```

This command passed on 2026-08-20. Its assertions require:

- active mode counts exactly `[43, 41, 41]`;
- each uniform forcing-mode k relative error < 1e-7 versus native MATLAB;
- each lateral forcing-mode k relative error < 1e-7 versus native MATLAB;
- uniform and lateral direct-energy relative errors < 1e-7 versus native MATLAB;
- uniform and lateral Love-number energy relative errors < 1e-7 versus native MATLAB.

Thus the old 1% raw-grid transform floor is retired for the MATLAB-faithful grid path. The legacy coefficient/SciPy path remains useful as a separate interface, but its transform mismatch is not a solver-validation limit and should not be quoted as the accuracy of pylov3d.

## Separate remaining energy-method caveat

The approximately 2.15% difference between direct volume-integrated dissipation and the independent Im(k)-based Love-number energy estimate remains present in both MATLAB and Python. It is therefore not a Python-port discrepancy. It remains a separate numerical/methodological question for absolute-heating work and should not be conflated with the now-closed spherical-harmonic transform issue.
